## Threshold scelto e motivo

**Threshold inclusione: `INCLUSION_THRESHOLD = 0.30`** (default SPEC §11).

### Motivazione

Con 200–500 entità per progetto e SPEC che cita 0.40 = "swallows missed match" / 0.25 = "noise", **0.30 è il default neutro**. La combinazione substring (≥0.70) + fuzzy capped a 0.60 (`FUZZY_CAP`) garantisce che:

- gli hit substring (es. `"electricity"` in `"electricity, low voltage IT"` → 0.78) restino nettamente sopra il rumore;
- il fuzzy puro produca score ~0.30–0.55 per match parziali (typo), affiorino ma non dominino mai i veri match.

### Da rivalutare

Dopo manual QA su un progetto reale ~200 BomRow:
- **se Mirko vede rumore** → alzare a `0.40`;
- **se vede missed match** (es. typo `"electricty"`) → abbassare a `0.25`.

Decisione = una sola riga in `INCLUSION_THRESHOLD` in `backend/services/global_search.py`.

## Carry-over emersi

1. **`flow` type → array vuoto** (documentato in SPEC §6 ed esplicito nel codice). Schema v6 non ha entità `Flow` separata: i flussi vivono dentro `BomRow.extra['flow_name']` e affiorano già via il tipo `bom_row`. Se in futuro Mirko aggiunge una collezione `project.flows` separata, basta riempire `_flow_results()` in `backend/services/global_search.py`.

2. **Frontend Command Palette ⌘K integration** → sprint **G1.x** dedicato. SPEC B1 era 100% backend per design.

3. **Cross-project search** → V2 (richiede multi-tenant).

4. **Embedding / semantic search** → V2. Overkill per modelli ~200–500 entità — la SPEC stessa lo dichiara out of scope.

5. **Caching backend** → post-multi-tenant. Per ora è ricalcolo a ogni request, sotto i 100 ms p95 con loop Python e difflib.

6. **Performance check p95 <100 ms** → atteso ma non misurato in CI (SPEC §11: "non ottimizzare prematuramente"). Da verificare con manual QA su progetto reale; se sfora, primo step è cache LRU sul tuple `(pid, q, types, limit)`, non rapidfuzz.

7. **Schema route `navigate_to`** — usate:
   - `bom_row` → `/projects/{pid}/match?row={row_id}` (esattamente come SPEC §5)
   - `process` → `/projects/{pid}/processes/{process_id}`
   - `parameter` → `/projects/{pid}/parameters/{name}`

   Se G3/G1.x preferisce route diverse, è una stringa template da cambiare in un punto per tipo.
